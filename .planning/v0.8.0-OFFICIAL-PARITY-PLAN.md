## 1. 背景

官方 Node / Python SDK 從 1.4.2 / 2.4.1 推進到 1.5.0-rc.5 / 2.5.0rc5，共 8 項變更。
本 repo 的 Rust core 目前對齊的是 1.4.2 / 2.4.1（vendored 參考副本 `fugle-marketdata-node/`、
`fugle-marketdata-python/` 仍停在舊版）。本計畫把 core 與四個 binding 軌道一次補齊。

### 1.1 官方變更盤點

| # | 變更 | 官方 commit | 我方狀態 |
|---|---|---|---|
| 1 | `stock.ownership.etfHoldings` REST 端點 | `07ec34c` / `refactor` `7494aa8` | ❌ 完全缺 |
| 2 | futopt 價差合約：symbol percent-encode（8 端點）、`tickers.isSpread`、`trades.isTrial` | `51e5926` | ⚠️ 僅 `isTrial` 有 |
| 3 | futopt `intraday/quote` 欄位大擴充 | `51e5926` | ⚠️ 舊 shape |
| 4 | WS futopt streaming 版本選項，futopt 預設 v1.1 | `3912cf8` | ❌ 完全缺 |
| 5 | futopt WS frame：`isTrial`、`derivedBid/Ask`、`serial`、`isReplaced` | `3912cf8` | ❌ 完全缺 |
| 6 | 健康檢查改 freshness-based + disconnect reason；`maxMissedPongs` clamp ≥ 1 | `43d2725` `4f04707` | ✅ 已領先 |
| 7 | **`baseUrl` 禁止含版本段，SDK 自己接 `/v1.0`** | `b8be8c6` | 🔴 語意衝突 |
| 8 | 暴露 resolved endpoint（`client.baseUrl` / `ws.url`） | `c3edb40` | ❌ 完全缺 |

### 1.2 #6 為何不用動

官方這次是把 ping/pong 漏接計數改成 freshness 檢查（`lastMessageAt < lastPingAt` 才記一次
miss），並在 close 事件補上 `{ reason: 'health-check-timeout' }`。

我方 0.3.0 起就是 async-native 的單一 timeout window：`dispatch_messages` 用
`tokio::time::timeout(heartbeat_timeout, ws_read.next())` 直接搶佔，逾時發
`ConnectionEvent::HeartbeatTimeout`。沒有背景輪詢、沒有 missed-pong 計數器，
`maxMissedPongs` clamp 問題在我方架構下不存在。

**結論：不修改，但要在 MIGRATION / 文件寫清楚兩者的對應關係**，避免使用者照官方文件找
`maxMissedPongs` 卻找不到。

### 1.3 #7 語意衝突（本輪最大的一顆）

- 我方 0.6.0：`base_url` **必須**含版本段（`core/src/urls.rs:16-20`、
  `core/src/websocket/factory.rs:105-120`），走 OpenAI / Stripe 慣例。
- 官方 1.5.0-rc.4：`baseUrl` **不得**含版本段，含了就丟 `TypeError`，版本段由 SDK 擁有，
  WS 版本改由新的 `version` 選項決定。

官方的理由（`src/base-url.ts` 註解）：兩個選項爭奪同一個 path segment 會逼出優先序規則，
而那些規則讓「只想換 host」的人被迫手動維護版本號。

**決策：跟進官方**（已與 owner 確認）。這是我方第二次改 `base_url` 語意，需要一份
講得很清楚的 `MIGRATION-0.8.md`。

### 2.1 為什麼 py/js 維持 3.0.0 而不是 3.1.0

py/js binding **從未發布過**。PyPI 上的 3.0.0、npm 上的 3.0.0 都還是空的，因此不存在
「3.0.0 已經代表 2.4.1 功能集」這個既有承諾要維護。我們直接把 3.0.0 重新定義成
**首發即對齊官方 1.5.0 / 2.5.0 功能集**即可。

這帶來一個很大的好處：**#7 的二次 breaking 只影響 crates.io 上的 Rust 使用者**
（0.6.0 / 0.7.x 已發布）。py/js/uniffi 的使用者從未見過 0.6.0 的 `base_url` 語意，
對他們而言這根本不是 breaking change，首發就是官方語意。

版號單調性檢查：PyPI `3.0.0rc1` > `2.5.0rc5` ✓；npm `3.0.0-rc.1` > `1.5.0-rc.5` ✓。

### 2.2 workspace 版號需要拆開

`Cargo.toml` 目前 `workspace.package.version = "3.0.0"`，由 `py` / `js` / `uniffi` /
`gui-web/src-tauri` 共用；`core` / `rust` 各自覆寫成 0.7.3。

要讓 uniffi 走獨立 0.x 軌，需要：

- `uniffi/Cargo.toml` 加上明確 `version = "0.1.0-rc.1"`（不再 `version.workspace = true`）
- `bindings/java/build.gradle.kts:7` 的 `projectVersion` 預設由 `3.0.0-dev` 改 `0.1.0-rc.1`
- C# `.csproj` / Go module 的版號一併確認（Go 走 tag，需注意 0.x 不用 `/vN` 後綴）
- `gui-web/src-tauri` 不發布，維持 workspace 版號即可

### 2.3 rc 節奏

跟著官方出 rc，等官方 GA 才轉正式：

- crates.io：`0.8.0-rc.1` 為 pre-release，`cargo add` 預設不會抓到
- PyPI：`3.0.0rc1`，`pip install` 預設不會抓到（需 `--pre`）
- npm：發到 `next` dist-tag，`latest` 保持空/舊
- 官方若在 rc.6+ 再改語意（特別是 #7），我方仍有調整空間

## 3. Core 工作項目（0.7.3 → 0.8.0-rc.1）

### A. `base_url` 語意反轉（BREAKING）

**檔案**：`core/src/urls.rs`、`core/src/rest/client.rs`、`core/src/websocket/factory.rs`

1. `urls.rs` 新增 `with_version(base: &str, version: &str) -> Result<String, MarketDataError>`
   對應官方 `src/base-url.ts`：
   - 去掉尾端 `/`
   - 若 match `/v\d+\.\d+$` → `Err(ConfigError)`，訊息要指出正確的 prefix（照抄官方措辭）
   - 否則回傳 `{trimmed}/{version}`
2. `REST_BASE` / `STOCK_WS` / `FUTOPT_WS` 常數保留（no-override 的快路徑），
   但文件註解全部改寫；`urls.rs:16-20` 那段 0.6.0 的說明要整段換掉。
3. `RestClient::base_url()` 改成接受 host+prefix，內部套 `with_version(..., API_VERSION)`。
4. `WebSocketFactory::base_url()` 同理，版本來自 §D 的 `version` 選項。

**待決的 Rust API 設計問題**：`base_url()` 是 builder 鏈上的 infallible method，
但驗證需要回報錯誤。三個選項：

| 選項 | 做法 | 評價 |
|---|---|---|
| (a) | `WebSocketFactory::{stock,futopt}()` 改回 `Result<ConnectionConfigBuilder, _>` | WS 端推薦。本輪本來就是 breaking，錯誤出現在最早的誠實時機 |
| (b) | `base_url()` 回 `Result<Self, _>` | builder 鏈中間插 `?`，很醜 |
| (c) | 存下 `base_url_error: Option<MarketDataError>`，在首次 `send()` 傳播 | REST 端推薦。`send()` 本來就回 `Result`，鏈式體驗不變（同 reqwest deferred-error 模式）|

**建議：WS 走 (a)、REST 走 (c)。**

**重要**：py/js binding 的 constructor 本來就回 `Result` / 會 throw，可以**即時**拋錯，
行為與官方 `TypeError` 完全一致。這個設計皺褶只存在於 Rust 原生 API。

### B. 新端點 `stock.ownership.etf_holdings`

**新檔**：`core/src/rest/stock/ownership/mod.rs`、`core/src/rest/stock/ownership/etf_holdings.rs`、
`core/src/models/ownership.rs`
**改檔**：`core/src/rest/stock/mod.rs`（掛上 `ownership()`）、`core/src/models/mod.rs`

- path：`ownership/etf-holdings/{symbol}`（symbol 走 path，其餘走 query）
- params：`symbol`(必填)、`from`、`to`、`sort`(`asc`/`desc`)
- response：`{ type?, exchange?, market?, symbol, data: [{ date, components: [...] }] }`
- component：`symbol`、`name`、`quantity`、`weight`、`quantityChange?`、`weightChange?`
- 注意官方 `7494aa8` 已把 `code` query param 拿掉（配合 server MR !376），**不要實作 `code`**

### C. futopt symbol percent-encoding（價差合約）

**檔案**：`core/src/rest/futopt/**`（8 支）、建議 `core/src/rest/stock/**` 一併加固

現況：`core/src/rest/**` 完全沒有任何 percent-encoding。價差合約 symbol 含 `/`
（如 `TXFC4/TXFD4`）會直接破壞 URL path，打到錯誤的 endpoint。

- 加 `percent-encoding` 或 `urlencoding` dependency（`percent-encoding` 較輕、無額外傳遞依賴）
- 對應官方 `encodeURIComponent` 語意：用 `NON_ALPHANUMERIC` set 再放行 `-._~`
- 涵蓋：futopt `intraday/{quote,ticker,trades,volumes,candles}`、
  `historical/{candles,daily}`，共 8 個 path 組裝點
- **測試必須包含含 `/` 的價差 symbol**，這是這項唯一有意義的驗證

### D. WS streaming 版本選項

**新檔**：`core/src/websocket/version.rs`
**改檔**：`core/src/websocket/factory.rs`、`core/src/websocket/mod.rs`

- 支援表：`stock: ["v1.0"]`、`futopt: ["v1.0", "v1.1"]`，最後一個為該產品 latest
- **futopt 預設變成 v1.1**（含試撮 frame）— 這是行為變更，要寫進 MIGRATION
- Rust 這邊有型別優勢，官方用 map + runtime TypeError，我方應該用 enum 讓不合法組合
  **編譯期就過不了**：

  ```rust
  pub enum StockVersion  { V1_0 }
  pub enum FutOptVersion { V1_0, V1_1 }

  WebSocketFactory::new()
      .auth(..)
      .futopt_version(FutOptVersion::V1_1)   // stock 版本無從誤用
  ```

  比官方的 `{ stock: 'v1.1' }` → runtime throw 更好，且不需要 `resolveVersion` 的
  「bare string 防呆」那一整段（Rust 沒有那個 footgun）。
- binding 層（py/js 動態語言）仍需保留 runtime 驗證與官方一致的錯誤訊息

### E. futopt REST model 補齊

**檔案**：`core/src/models/futopt/quote.rs`

`FutOptQuote`（`quote.rs:80`）目前是 spec-not-payload 的舊 shape，0.7.2/0.7.3 的
decode 修正沒掃到這支。需要：

- 新增：`market`、`priceLimits{price,bid,ask,curb}`、`lastTrial`、`tradingHalt`、
  `isTrial`、`isDelayedOpen`、`isDelayedClose`、`isContinuous`、`isOpen`、`isClose`、`serial`
- `FutOptTotalStats`（`quote.rs:16`，目前僅 3 欄）補：`tradeValue`、`tradeVolumeAtBid`、
  `tradeVolumeAtAsk`、`transaction`、`time`
- `FutOptLastTrade`（`quote.rs:30`，目前僅 3 欄）補：`bid`、`ask`、`serial`
- `name` / `previousClose`：官方已移除，我方**保留為 `Option` 不刪**，避免舊 payload 解不動
- doc example（`quote.rs:45-79`）的 JSON 要換成真實 payload
- `tickers`：`isSpread` 加入 request builder 與 response（`core/src/rest/futopt/intraday/tickers.rs`）

⚠️ **所有欄位必須對真實 payload 驗證，不是照 TypeScript interface 抄** —— 這正是
0.7.2 那次大修的教訓。用 `core/examples/prod_smoke` 打實際 endpoint 比對。

### F. futopt WS frame 型別

**檔案**：`core/src/models/streaming.rs`、`core/src/websocket/channels/parser.rs`

- `TradesData`（`streaming.rs:122`）、`BooksData`（`streaming.rs:221`）加 `is_trial: Option<bool>`
  （server 為 false 時整個省略，不送 `isTrial: false`）
- `BooksData` 加 `derived_bid` / `derived_ask`（第 6 檔延伸委託簿）
- `StreamTrade`（`streaming.rs:150`）加 `serial`、`is_replaced`
- **設計決策待定**：目前 `TradesData` / `BooksData` 是 stock/futopt 共用。官方拆出獨立的
  `WebSocketFutOptTradesData` / `WebSocketFutOptBooksData`。
  - 選項 1（建議）：共用結構加 `Option` 欄位 —— 改動小，stock 端該欄位恆為 `None`
  - 選項 2：拆成 futopt 專屬型別 —— 型別更精確，但 `parser.rs` 的 `ChannelData` enum
    要按產品分支，牽動所有 binding 的 callback 型別，成本明顯較高
- `aggregates` channel：官方註明它**不受版本 gate**，試撮期間 `lastPrice`/`lastSize`
  就是試撮值，只有 top-level `isTrial` 能區分。這點務必寫進 doc comment。
